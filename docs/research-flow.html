Step 01 — 問題定義

問題唔係「邊匹會贏」

Benter 嘅框架從來唔係一個 picks-and-shoots。佢分兩階段，兩階段都有嚴格嘅輸出要求。 搞清楚呢一點，之後所有實驗設計（用 log-loss 唔用 hit rate、點解要 de-vig、點解要 null test）都係自然推導出嚟。

階段一 · 算出基本概率

用 multinomial logit 加 100 多個賽前因子 （檔位、評分、磅重、騎練勝率⋯⋯）估計每匹馬嘅勝率。

P(i 贏) = exp(xᵢβ) / Σⱼ exp(xⱼβ)
同一場內加總 = 1，所以輸出本身就係概率

階段二 · 融合市場價格

將自己嘅概率同市場隱含概率合併，再喺「合併概率 × 賠率 > 1」時落注，用分數 Kelly 配注。

cᵢ = softmax(α·log fᵢ + β·log πᵢ)
π = 除去抽水後嘅市場概率
呢個框架決定咗用乜 metric 評分
要答嘅問題用嘅指標點解唔可以用其他
模型準唔準？log-losshit rate 獎勵運氣；log-loss 獎勵誠實
校準得唔得？reliability curve講「20% 嘅馬係咪真係贏 20%」
知得比市場多唔多？R² vs 市場log-loss 好過市場都一樣可能冇錢賺
值唔值得落注？計抽水後 ROI命中率同價值無關
個結果係真定假？null test個 backtest 如果永遠賺錢，就係壞嘅

Step 04 — 防泄漏

賽馬項目通常死喺呢度

呢啲唔係「做得好啲」嘅要求，係「個結果可信唔可信」嘅要求。所以全部寫入 code，唔靠紀律。

四道閘

  • 01只用嚴格更早嘅日期 —— 賽事日 d 嘅特徵只可以用 meeting_date < d 嘅賽事。同一日嘅都唔用。
  • 02賽後欄位永遠唔會變成特徵 —— 用 assertion 硬性把關，唔靠「記得唔好加」。
  • 03填補統計只用 training split —— 用全份 data 嘅中位數，會令每個特徵依賴全份資料。
  • 04覆蓋率偏移警報 —— 特徵喺 train/test 出現率差太遠 → 報警。
真實捉到嘅一個 leakage

「年齡」欄位其實係未來數值

HKJC 喺馬匹頁公佈嘅係收集當日嘅年齡。 所以一場 2018 年嘅賽事，呢欄裝住馬匹 2026 年嘅年齡。

Step 05 — Null test

整個項目最關鍵的一個檢查

模擬器嘅市場係可以調嘅，可以調到最優 —— 市場知晒所有嘢，冇嘢可以賺。呢個情況下如果仲顯示正數 ROI， 代表個框架製造緊利潤，其他所有數字都冇意義。

結論一

市場贏，而且贏得好遠

所有 standalone model 輸市場約 8%。而 de-vig 咗嘅市場校準得好難得：最低概率桶預測 4.9%、實際贏 4.6%；最高桶預測 26%、實際 27.5%。

基準係公平嘅，所以差距係真嘅。

結論二

NN 改變唔到分數

C (2.2921) 同 A (2.3009) 喺同一個水平。Listwise MLP、field transformer、conditional logit、LightGBM 全部企埋一齊。

唯一分別：NN 校準最好（ECE 0.0029 vs 0.0036 vs 0.0092），hit rate 亦最高（0.219）。

結論三

融合層學識咗「信市場」

MLE 自己學到 α = 0.36（模型）同 β = 0.88（市場）—— 佢自己發現市場值得大部分權重。

F 只贏市場 +0.45%。Benter 第二層冇壞，係冇嘢可以 fuse。

Step 09 — 結論同下一步

缺嘅唔係模型，係資訊

> 答案：唔會。 喺真實 HKJC 公開資料上建立嘅基本面模型，冇一個贏得過市場；類神經網絡亦冇。 呢個結論係框架自己跑出嚟嘅 —— null test 之下利潤製造唔到。
呢個係有用嘅結果。如果當初用一個有 leakage 嘅 backtest，你會得到相反嘅結論，然後輸錢。

下一步：加資訊
